## Key Interactions to Verify

### 시간 그리드 (모바일 + 웹)
- 드래그 sweep 멀티 셀렉트 시작 (long-press + sweep)
- 드래그 중 셀이 시각적으로 즉시 색 변화
- 드래그 끝 시 한 번에 server commit (debounce)
- 이미 선택된 셀 위로 sweep 시 toggle off
- 09:00 / 24:00 경계 셀에서 작동
- 다일 (multi-day) span (행 전환 시)
- 60fps 유지 (저사양 디바이스 iPhone SE 2 + Galaxy A14)

### 실시간 히트맵
- 다른 멤버 투표 시 100ms 안에 색 update
- 5명 동시 투표 시 jank 없음
- 모임 멤버 수 변화 시 max scale 자동 조정
- 연결 끊김 시 명시적 UI ("연결 끊김, 재시도 중")
- 재연결 시 stale local state → server state 정확히 sync

### 카카오 OAuth
- 첫 로그인 시 약관 모달 노출 (필수 동의 강제)
- 재로그인 시 기존 user 매칭 (Supabase Auth가 `id_token.sub` 기반 자동 매칭)
- 동시에 두 디바이스에서 같은 사용자 로그인 (정상 동작)
- 토큰 만료 시 silent refresh 시도 + 실패 시 재로그인 안내

### 모임 만들기 → 확정 → 장소
- 친구 0명 + 게스트 링크만 (가능해야 함)
- 친구 다중 선택 + 카톡 공유 링크 생성
- 호스트가 시간 확정 후 멤버에게 푸시 F5 + Calendar push
- 더블 탭 확정 (idempotency — 한 번만 처리)
- "장소만 정하기" → 카톡 공유 → 흐름 종료
- "예약하기" 클릭 → click-through event 정확히 1개 로깅
- click 후 Phase 1+2 안내 → 사용자 confusion 없음

### 게스트 투표 (웹)
- 카톡 인앱 브라우저 진입 (iOS·Android 양쪽)
- 닉네임 입력 모달 첫 진입 시
- 브라우저 토큰 발급 → localStorage 저장
- 같은 브라우저 다음 진입 시 토큰 매칭 (닉네임 자동 입력)
- 모바일 브라우저만 (데스크톱은 fallback 안내)
- "결과 알림 받기" CTA → Branch.io 단축 URL → App Store
- 카톡 OG 미리보기 (메타 태그 작동)

### Branch.io 게스트→회원 전환
- 웹 게스트 투표 → 앱 설치 → 자동 attribution (한국 NAT 환경 ≥ 70% target)
- 24h 이내 install → attribution 성공
- 24h 이상 gap → fallback ("초대받은 모임 코드 입력" 수동 입력)
- 동일 디바이스 두 게스트 토큰 (다른 모임 두 번 참여) → 둘 다 매칭
- attribution 실패 시 사용자 안내 + 수동 fallback

### Calendar sync
- Google Calendar 첫 인증 → "어디 추가할까요?" 모달 + 기억
- 모임 확정 시 모든 동의 멤버에게 push
- Apple Calendar (iOS only) — expo-calendar `createEventAsync`
- iOS 17+ write-only 권한만 요청 (read 권한 X)
- 권한 거부 시 silent fail 금지 — 명시 안내
- Push 부분 실패 (10명 중 3명) → 호스트에게 partial fail report
- Token 만료 시 프로필에 "재인증 필요" 상태

### 지도 + 카카오 Local API
- Viewport 이동 → 300-500ms debounce → API 호출
- 카테고리 필터 (제휴 / 음식점 / 술집 / 파티룸 / 지하철역) 다중 선택
- 반경 조절 바 (우측)
- 좌표계 정규화 (모든 외부 좌표 WGS84 확인)
- 5분 viewport 격자 캐싱 (재방문 시 API skip)
- 줌 아웃 시 클러스터링 ("음식점 23곳")
- 제휴 마커 강조 (보라 #7C3AED, 1.3-1.5배 크기)
- 마커 50+ 시 60fps 유지

### 에브리타임 OCR (D2: Phase 1+2 유지)
- 학교 시간표 스크린샷 업로드 → Gemini Vision 호출 → JSON 결과 미리보기
- 학기 시작·종료일 입력 모달 (date picker)
- OCR 결과 confirm 단계 (사용자가 수정·삭제 가능)
- Confirm 시 매주 반복 일정 `schedules` table에 INSERT (source = 'everytime')
- 학기 종료일 도래 시 일정 자동 만료 (UI에서 숨김)
- 카메라·갤러리 권한 거부 흐름 (안내 모달)
- OCR 오인식 → 사용자 수정 가능 (silent fail 금지)
- 한 학교 = 한 OCR 결과, 두 번째 import 시 기존 데이터 덮어쓰기 또는 추가 결정 UI
- **OCR 외부 캘린더 push 안 함** (학기 시간표 폭격 회피, 권고)

### "지도로 내 일정 보기" 모드 (D2: Phase 1+2 유지)
- 홈 캘린더 우상단 "지도로 보기" 토글 → 지도 mode 전환
- 일정 데이터 (좌표 있는 모임 일정만 — Google·Apple 일정은 차기)
- 시간 순서대로 ①②③ 숫자 배지 마커
- 보라 #7C3AED 점선 2pt 폴리라인
- 마커 5개 초과 시 폴리라인 자동 숨김 (가장 가까운 두 점만)
- 시간 범위 토글: 오늘 / 이번 주 / 이번 달
- 좌표 없는 일정 (장소 미확정 모임) → 마커 0, "장소 정해진 모임이 없어요" UI
- 일정 마커 클릭 → 모임 상세로 이동
- mode 전환 시 매장 검색 마커 OFF + 카카오 Local API 호출 안 함

### 친구 / 신고 / 차단
- 친구 추가 (전화번호 + 닉네임 검색)
- 친구 요청 보내기 → 받기 → 수락 → 푸시 F2
- 차단된 사용자 → 친구 검색에서 제외
- 차단된 사용자 → 친구 추천에서 제외
- 같은 모임 멤버 차단 시 → 멤버 list 표시 유지, 코멘트 hidden
- 신고 → 운영팀 카톡 채널로 manual 전달 확인

### 푸시 알림 (F1-F5 Phase 1+2)
- 알림 권한 거부 흐름 (안내 모달)
- F1 친구 요청 받음 → friends 탭으로 deeplink
- F2 친구 요청 수락 → friends 탭
- F3 모임 초대 → group/[id] deeplink
- F4 모든 참여자 투표 완료 (호스트 only, 한 모임당 1회 idempotent)
- F5 시간/장소 확정 (회원 멤버만, 게스트 제외)
- 알림 설정 카테고리 토글 (소셜·모임·예약) 작동
- 푸시 token 등록 + 디바이스 변경 시 갱신

## Edge Cases

### 시간 그리드
- 0시 0분에 1셀 선택 (정확한 minute 저장)
- 23시 45분~24시 00분 셀 (마지막 셀)
- 7일 전부 0개 슬롯 (투표 안 함 → vote row INSERT 0개)
- 7일 전부 모든 슬롯 (vote row 매우 많음 → 성능)

### 카카오 OIDC OAuth
- `id_token.sub` claim 유일성 (Supabase Auth가 provider_id로 unique 보장. 두 다른 카카오 id → 다른 user)
- 카카오 nickname 특수문자 (이모지, 유니코드 RTL)
- 같은 카카오 user가 다른 디바이스에서 첫 로그인 → 단일 user_id 유지

### 게스트 토큰
- 같은 브라우저, 다른 모임 두 번 (각 모임마다 별도 토큰)
- 시크릿 모드 (localStorage 없음 → 새 토큰 매번)
- localStorage 정리 후 재방문 → 새 게스트로 인식 (의도된 동작)

### 시간대
- 사용자 디바이스 시간대 = UTC (해외 출장 중 한국 모임 시간 표시)
- 사용자 디바이스 시간대 = Asia/Seoul (정상)
- 자동 일광 절약 시간 (DST) — 한국 무관이지만 외국 여행 시 lib 동작

### Calendar
- Google Calendar 사용자가 push 후 외부에서 일정 삭제 → 우리 앱은 유지 (의도)
- Google Calendar 사용자가 push 후 외부에서 시간 수정 → 우리 앱은 유지
- iCloud Apple Calendar에 같은 일정 두 번 push 시도 → 중복 방지
- 사용자가 캘린더 연결 OFF 후 다시 ON → 재인증 흐름

### 지도
- GPS 없는 사용자 → default 위치 (지정된 hotspot, 강남 또는 홍대)
- 한국 영역 밖으로 viewport 이동 시 (`isExtentBoundedInKorea`로 차단)
- Kakao Local API rate limit hit → fallback UI + 캐시 우선
- 마커 0개 (검색 결과 없음) → empty state UI

### 차단/신고
- 같은 사용자 차단 두 번 (idempotent)
- 차단된 사용자가 만든 모임에 초대됨 → 초대장 hidden 또는 "차단됨" 라벨
- 자기 자신 차단 시도 (UI에서 차단)

### Realtime
- 100명 (베타엔 안 발생하지만) 동시 모임 투표 stress test
- Supabase Realtime quota 한도 (free tier 200 connection) → fallback

## Critical Paths (end-to-end)

### CP1: 게스트 → 회원 전환 (growth loop 핵심)
1. 카톡 게스트 링크 클릭 (인앱 브라우저)
2. 닉네임 입력 + 시간 투표 + 결과 확인
3. "결과 알림 받기" CTA → App Store install
4. 앱 첫 실행 → 카카오 로그인 → 약관 동의 → 온보딩
5. Branch.io attribution 매칭 성공
6. 자동 모임 멤버 합류 + 모임 list에 표시

### CP2: 호스트 모임 만들기 → 확정 → click-through (Gate metric)
1. (+) FAB → 모임 만들기
2. 이름·날짜·시간 그리드 입력 + 친구 다중 초대
3. 카톡 공유 링크 생성
4. 친구들 투표 → 실시간 히트맵 update
5. 모든 멤버 투표 완료 → 호스트에게 F4 푸시
6. 호스트 시간 확정 → 멤버에게 F5 푸시 + Calendar push
7. 모임 상세에 "장소 정하기" 섹션 노출
8. "예약하기" 탭 → 지도 → 마커 → 바텀시트 → click event 로깅
9. "Phase 1+2: 준비 중" 안내 (또는 silent)

### CP3: 호스트 + 멤버 동시 작동 (성능 + 일관성)
1. 호스트 모임 만들기 + 5명 초대
2. 호스트 + 5명이 동시에 시간 그리드 진입 (Realtime channel 6 connection)
3. 동시 투표 (각자 다른 셀 sweep)
4. 모든 클라이언트가 100ms 안에 heatmap update 받음
5. 호스트 시간 확정 → 5명 모두 푸시 + Calendar push 받음
6. 모든 멤버의 모임 상세에 "장소 정하기" 섹션 동기화 노출

### CP4: 새 사용자 첫 사용 (onboarding 완주율)
1. 앱 설치 (Branch attribution X 또는 organic)
2. 첫 실행 → 카카오 로그인
3. 약관 동의 모달 → 필수 동의
4. 3 슬라이드 온보딩 (스킵 가능)
5. 홈 화면 진입 (빈 캘린더 + 친구 추가 안내)
6. 친구 추가 또는 모임 만들기 진입

### CP5: 권한 거부 흐름 (silent fail 검증)
1. 카메라 권한 거부 (OCR 제외 시 N/A)
2. 푸시 알림 권한 거부 → 알림 설정 UI에서 명시
3. Calendar 권한 거부 → 첫 모임 확정 시 안내 모달
4. 위치 권한 거부 → 지도 default 위치 + 안내

### §3.1 Jest + RN testing-library

Unit / Integration 테스트의 기본 패턴.

```tsx
// src/components/TimeGrid/TimeGrid.test.tsx
import { render, screen, fireEvent } from '@testing-library/react-native';
import { TimeGrid } from '@/components/TimeGrid';
import { tokens } from '@/design/tokens';

describe('TimeGrid', () => {
  it('drag sweeps multi-select cells (D12)', async () => {
    render(<TimeGrid groupId="test-group" />);
    const cell0 = screen.getByTestId('cell-09-00');

    // Reanimated worklet은 unit test에서 mock 필요
    fireEvent(cell0, 'gestureStart');
    fireEvent(cell0, 'gestureUpdate', { x: 0, y: 100 }); // sweep down
    fireEvent(cell0, 'gestureEnd');

    // 본인 슬롯 = brand-50 + 보더 (DESIGN §10.1)
    expect(cell0).toHaveStyle({ backgroundColor: tokens.light.brand[50] });
  });

  it('cell touch is idempotent on double tap', async () => {
    render(<TimeGrid groupId="test-group" />);
    const cell = screen.getByTestId('cell-19-30');
    fireEvent.press(cell);
    fireEvent.press(cell);
    // 같은 슬롯 vote insert는 1회만 (D14 + idempotency)
    expect(mockSupabaseInsert).toHaveBeenCalledTimes(1);
  });
});
```

**Reanimated worklet mock**: `jest-setup.ts`에 `jest.mock('react-native-reanimated', () => require('react-native-reanimated/mock'))` 필수.

### §3.2 Maestro E2E (모바일)

User flow 단위 E2E. iOS·Android 양쪽.

```yaml
# maestro/host_create_group.yaml
appId: com.denda.app
---
- launchApp
- tapOn: "(+)"  # FAB
- inputText:
    id: "group-name-input"
    text: "팀플 모임"
- tapOn: "다음"

# 시간 그리드 드래그 sweep
- tapOn:
    id: "cell-2026-05-22-1900"  # KST
- swipe:
```
